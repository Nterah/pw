Affinity

White-label Church Community App • Multi-tenant • Theme System

Summary

Affinity is a white-label SaaS platform that gives churches a fully branded, mobile-first community app. Each church operates as an isolated tenant with its own theme, content and member experience, while running on shared infrastructure. It’s built for privacy-first access, brand consistency, and scalable growth into richer community modules.

  • Pre-login church selection (privacy-first; no public directory)
  • Tenant branding/theme system (colors, logos, UI styling)
  • Strict tenant isolation (no cross-tenant visibility)
  • Mobile-first member and admin experiences
  • Scalable base for community modules

At a glance

Who it’s for
  • Church leadership and admin teams
  • Church members using a mobile-first community app
  • Multi-campus organisations needing white-label branding
What it solves
  • High cost of building a custom app per church
  • Generic platforms that don’t reflect each church’s brand
  • Privacy concerns with public church directories

Problem

Churches want modern digital engagement (resources, announcements, events) but often can’t justify a fully custom build. Members expect a branded experience and privacy controls that avoid open directories.

Solution

Affinity provides a multi-tenant platform with strict isolation and a reusable theme system, so each church feels like it has its own dedicated app without needing separate codebases.

Key workflows

  • Church admin configures tenant branding (logo, colors, theme)
  • Members access via invite or direct link and select church before login
  • Members consume church-specific content and participate in community features
  • Admins manage content and settings with no cross-tenant visibility

Notable features

  • Pre-auth church selection and privacy-first access model
  • No public directory; invite/direct-link approach
  • Complete branding isolation per tenant
  • Theme helper utilities for consistent UI across components
  • Scalable architecture for adding community modules over time

Tech / Architecture

  • Frontend: React + TypeScript, Tailwind CSS
  • UI: component-driven design (shadcn/ui patterns), Lucide icons, toast system
  • Tenant isolation model embedded into routing and app structure

Challenges & decisions

  • Ensuring tenant isolation while keeping onboarding simple
  • Building a theme system that scales without duplication
  • Designing for privacy: no public directory, invite-first access

Results / impact

  • Enables churches to launch branded apps without separate codebases
  • Improves member trust through privacy-first tenant selection
  • Provides a scalable base for future community expansion
