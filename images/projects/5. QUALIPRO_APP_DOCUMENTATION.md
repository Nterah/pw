## Executive Summary

### What QualiPro Is
QualiPro is an **inspection-first mobile application** for engineering consultants to manage Project Quality Plans (PQP) on-site with offline support, designed for construction and engineering projects in South Africa.

### Current State
The app is a **partially implemented prototype** using a Key-Value (KV) store for data persistence. It has basic multi-tenant architecture, project management, and PQP section CRUD operations, but is **missing critical quality management workflow modules** (NCR, CAPA, Inspections, Gates, Checklists).

### Deployment Status
- **Frontend**: React + Tailwind CSS (v4)
- **Backend**: Supabase Edge Functions (Hono server)
- **Database**: KV store (`public.qualipro_kv_store`) - temporary solution
- **Target Schema**: `qualipro.*` (relational tables) - not yet implemented

## How the App Works

### 1. Application Startup Sequence

#### Step 1: Splash Screen
- Shows QualiPro logo with teal-to-orange gradient
- Displays for 2 seconds
- Sets initial loading state

#### Step 2: Context Initialization
```javascript
// /utils/app-context.tsx - initializeApp()
1. Check localStorage for 'qualipro_db_seeded' flag
2. If not seeded → Call POST /make-server-06a53f58/seed
3. Load tenants from KV store (GET /tenants)
4. Select default tenant (test Ngobe (Pty) Ltd) if isDefault=true
5. Store tenantId in localStorage
6. Set isLoading=false
```

#### Step 3: Tenant Selection Logic
```typescript
// Automatic default selection
const defaultTenant = tenantsData.find((t) => t.isDefault === true);
const selectedTenantId = defaultTenant 
  ? defaultTenant.tenant_id 
  : tenantsData[0].tenant_id;
```

**Result**: App loads showing "test Ngobe (Pty) Ltd" as active tenant

#### Step 4: Home Screen Render
- Displays overall dashboard
- Shows tenant-filtered data:
  - Active projects count
  - Open risks count
  - Recent uploads
  - Quick action buttons

### 2. Multi-Tenant Architecture

#### Tenant Structure
```typescript
interface Tenant {
  tenant_id: string;        // e.g., "tenant-002"
  company: string;          // e.g., "test Ngobe (Pty) Ltd"
  email: string;
  phone: string;
  address: string;
  isDefault: boolean;       // true for default tenant
  extra: Record<string, any>;
}
```

#### Current Tenants
1. **test Ngobe (Pty) Ltd** (tenant-002)
   - Default tenant (isDefault: true)
   - 1 sample project
   - Auto-selected on first load

2. **Original Tenant** (tenant-001)
   - Secondary tenant (isDefault: false)
   - 3 sample projects
   - Can be selected via tenant switcher

#### Tenant Switching Flow
```
1. User clicks tenant icon in AppBar
2. TenantSwitcher modal opens
3. Shows list of available tenants
4. User selects different tenant
5. setTenantId(newId) called
6. localStorage updated
7. All components re-render with new tenant filter
8. Data automatically scoped to new tenant
```

#### Data Scoping by Tenant
All API calls include tenant_id filter:
```javascript
GET /projects?tenant_id=tenant-002
GET /risks?tenant_id=tenant-002
GET /uploads?tenant_id=tenant-002
```

### 8. Data Persistence

#### Current Implementation: KV Store
**Table**: `public.qualipro_kv_store`

**Structure**:
```sql
CREATE TABLE public.qualipro_kv_store (
  key TEXT PRIMARY KEY,
  value JSONB
);
```

**Key Patterns**:
```
tenants:list              → Array of all tenants
tenant:{id}               → Individual tenant object
projects:list             → Array of all projects
project:{code}            → Individual project object
risks:list                → Array of all risks
uploads:list              → Array of all file uploads
team:list                 → Array of all team members
section:{code}:{id}       → Section data (e.g., section:PRJ-2024-001:2)
```

**Why KV Store?**
- Temporary solution for rapid prototyping
- Avoids complex schema migrations during development
- Easy to seed sample data
- Will be replaced with full relational schema

2. Offline Support (3-4 weeks)

Focus on **Phase 1 (Foundation)** and **Phase 2 (Quality Management Core)** to create a production-ready MVP that addresses the critical gaps while providing core quality management capabilities that engineering consultants require.

The current implementation provides a solid architectural foundation but needs significant feature development before it can be used in production for actual site inspections and quality management workflows.
