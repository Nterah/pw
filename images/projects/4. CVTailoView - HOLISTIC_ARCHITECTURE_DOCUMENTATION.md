## 1. Executive Overview

### 1.1 What is CVTailorView?

**CVTailorView** is a comprehensive, multi-tenant SaaS platform designed specifically for consultancy firms, engineering companies, and professional services organizations that participate in competitive tender bidding. It transforms the traditionally chaotic and error-prone tender submission process into a streamlined, requirements-driven workflow.

### 1.2 Core Value Proposition

- **Increase Win Rates** by ensuring submissions comply with the 10 critical tender questions
- **Reduce Submission Time** from weeks to hours through intelligent CV matching and automated document generation
- **Eliminate Non-Compliance Risks** with built-in requirements tracking and validation
- **Professional Presentation** with branded, tender-specific document exports

### 1.3 Target Users

- **Primary**: Engineering consultancies, construction management firms, project management consultancies
- **Geographic Focus**: South Africa (CIDB, ECSA, SACPCMP compliance built-in)
- **Company Size**: 10-500 employees with 50-200+ CVs in database
- **Key Personas**: Tender managers, HR departments, business development teams, project managers

### 2.2 Architecture Pattern: Three-Tier Architecture

- React 18 + TypeScript application
- Tailwind CSS v4 for styling

### 4.4 Row Level Security (RLS)

**All tables have RLS enabled** to enforce multi-tenant isolation:

```sql
-- Example RLS policy on personal_details
CREATE POLICY "Users can view their tenant's personnel"
  ON personal_details FOR SELECT
  USING (tenant_id IN (
    SELECT tenant_id FROM core.users WHERE id = auth.uid()
  ));

-- Example RLS policy on tender_leads
CREATE POLICY "Users can manage their tenant's tenders"
  ON tender_leads FOR ALL
  USING (tenant_id IN (
    SELECT tenant_id FROM core.users WHERE id = auth.uid()
  ));
```

**Key RLS Features:**
- Complete tenant data isolation
- User can only access their organization's data
- Role-based permissions within tenant
- Admin users have full tenant access

## 10. Security & Multi-Tenancy

### 10.1 Multi-Tenant Architecture

**Tenant Isolation:**
- Every user belongs to exactly ONE tenant
- All data tables have `tenant_id` foreign key
- Row Level Security (RLS) enforces isolation
- Users can ONLY access their tenant's data

**Tenant Identification:**
```typescript
// User record includes tenant_id
{
  id: 'user-uuid',
  email: 'user@example.com',
  tenant_id: 'tenant-uuid',
  role: 'admin'
}

// All queries filtered by tenant
SELECT * FROM personal_details 
WHERE tenant_id = 'current-user-tenant-id';
```

### 10.2 Row Level Security (RLS)

**Policy Structure:**
```sql
-- Enable RLS on table
ALTER TABLE personal_details ENABLE ROW LEVEL SECURITY;

-- Policy: Users can only see their tenant's data
CREATE POLICY "tenant_isolation_select" 
  ON personal_details FOR SELECT
  USING (
    tenant_id IN (
      SELECT tenant_id FROM core.users WHERE id = auth.uid()
    )
  );

-- Policy: Users can only insert into their tenant
CREATE POLICY "tenant_isolation_insert" 
  ON personal_details FOR INSERT
  WITH CHECK (
    tenant_id IN (
      SELECT tenant_id FROM core.users WHERE id = auth.uid()
    )
  );

-- Policy: Users can only update their tenant's data
CREATE POLICY "tenant_isolation_update" 
  ON personal_details FOR UPDATE
  USING (
    tenant_id IN (
      SELECT tenant_id FROM core.users WHERE id = auth.uid()
    )
  );

-- Policy: Users can only delete their tenant's data
CREATE POLICY "tenant_isolation_delete" 
  ON personal_details FOR DELETE
  USING (
    tenant_id IN (
      SELECT tenant_id FROM core.users WHERE id = auth.uid()
    )
  );
```

**Benefits:**
- Database-level security (not just application-level)
- Impossible for user to access other tenant's data
- No code changes needed to enforce isolation
- Protects against SQL injection and bugs

### 10.3 Authentication & Authorization

**Authentication:**
- Supabase Auth handles user credentials
- JWT tokens for session management
- Automatic token refresh
- Protected routes in React Router

**Authorization (Role-Based Access Control):**

| Role | Permissions |
|------|-------------|
| **Admin** | Full system access, user management, billing |
| **Manager** | Tender management, CV management, team assignment |
| **User** | View-only access, basic CV search, export |
| **External** | CV submission only (via capture link) |

**Implementation:**
```typescript
// Check user role
if (user.role === 'admin') {
  // Show admin features
}

// RLS policy with role check
CREATE POLICY "admins_full_access" 
  ON personal_details FOR ALL
  USING (
    EXISTS (
      SELECT 1 FROM core.users 
      WHERE id = auth.uid() 
      AND role = 'admin'
      AND tenant_id = personal_details.tenant_id
    )
  );
```

**Security Measures:**
