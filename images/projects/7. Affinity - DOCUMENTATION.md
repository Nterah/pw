## Executive Overview

**Affinity** is a white-label SaaS platform that provides churches with fully branded mobile-first community applications. Each church gets its own customized app experience with unique branding, colors, and content—all while running on a shared infrastructure.

### Core Value Proposition

- **True White-Label Experience**: Members never see "Affinity" branding—only their church's identity
- **Privacy-First Architecture**: No public church directories; each church's data is completely isolated
- **Pre-Login Church Selection**: Members choose their church before authentication, ensuring correct branding from the first screen
- **Dramatic Visual Differentiation**: Each church has distinct themes with background images, gradients, and color schemes

### Target Users

1. **Church Administrators**: Set up and manage their church's branded app experience
2. **Church Members**: Access their church's community features, resources, and connect with other members
3. **Affinity Platform Team**: Onboard new churches and manage the platform

## Multi-Tenant System

### Architecture Overview

Affinity uses a **single-tenant architecture** where each church operates as a completely isolated tenant with its own branding, data, and user experience.

### Key Principles

1. **No Cross-Tenant Visibility**: Members of one church cannot see or access another church's data
2. **Pre-Authentication Church Selection**: Users select their church BEFORE logging in
3. **No Public Directory**: Churches are not publicly searchable; members need direct links or invitations
4. **Complete Branding Isolation**: Each church's theme is applied immediately after selection

### Tenant Data Structure

Each church (tenant) maintains:

```typescript
interface ChurchData {
  name: string;              // Full church name
  initials: string;          // 2-4 character abbreviation
  primaryColor: string;      // Hex color for accents (#5eb3e4)
  backgroundColor: string;   // Solid color or gradient CSS
  backgroundImage?: string;  // Optional background image URL
  backgroundStyle: 'solid' | 'gradient' | 'image';
  textColor?: string;        // Text color override
  tagline?: string;          // Subtitle for church
  welcomeMessage?: string;   // Home screen message
  memberCount: number;       // Total members
  status: string;            // Active/Inactive
}
```

### Tenant Isolation Layers

1. **Visual Isolation**: Complete UI theming per church
2. **Data Isolation**: Separate data stores per church (future backend implementation)
3. **Authentication Isolation**: Church-specific login flows
4. **Content Isolation**: Each church has unique resources, events, groups, etc.

## Theme System

### Overview

The theme system is the backbone of the white-label experience, ensuring each church has a completely unique and branded interface.

### Theme Helper (`/utils/theme-helper.ts`)

The `generateChurchTheme()` function converts church branding data into a complete theme object:

```typescript
interface ChurchTheme {
  primary: string;           // Primary brand color
  primaryLight: string;      // Lightened variant (+40%)
  primaryDark: string;       // Darkened variant (-20%)
  cardBg: string;           // Gradient for card backgrounds
  cardBorder: string;       // Border color with opacity
  textPrimary: string;      // Primary text color
  textSecondary: string;    // Secondary text color
  accentGradient: string;   // Gradient for CTAs
  backgroundStyle: object;  // Complete background styling
}
```

### Background Styles

**Solid Color**:
```css
backgroundColor: "#0a1929"
```

**Gradient**:
```css
background: "linear-gradient(135deg, #1a0f0a 0%, #4a1f0f 50%, #1a0f0a 100%)"
```

**Image with Overlay**:
```css
backgroundImage: "linear-gradient(rgba(0, 0, 0, 0.75), rgba(0, 0, 0, 0.75)), url(...)"
backgroundSize: "cover"
backgroundPosition: "center"
backgroundAttachment: "fixed"
```

### Theme Application

Every tenant-level screen applies the church theme:

```tsx
const theme = generateChurchTheme(church);

<div style={theme.backgroundStyle}>
  <Card style={{ 
    background: theme.cardBg,
    borderColor: theme.cardBorder 
  }}>
    <Button style={{ background: theme.accentGradient }}>
      Action
    </Button>
  </Card>
</div>
```

### Color Utilities

- `adjustColor(hex, percent)`: Lighten or darken colors
- `withOpacity(hex, opacity)`: Add transparency to hex colors
- `getContrastText(hexColor)`: Calculate readable text color
- `getChurchColor(church)`: Handle both `color` and `primaryColor` properties

## User Flow & Navigation

### Complete User Journey

#### 1. Platform Entry (Affinity Landing)
```
User arrives → Affinity Landing Page
                  ↓
        Three possible paths:
        1. "Church admin login" → Admin Dashboard
        2. "Start for your church" → Church Sign-up Flow
        3. "Member sign in" → Church Selection Screen

```
Member sign in button clicked
        ↓
Church Selection Screen
        ↓

        ↓

        ↓
Branded Login Screen (Grace City theme applied)
        ↓

        ↓
Member Home Dashboard (fully themed)
```

#### 3. Church Admin Flow
```
Admin login
        ↓
Admin Dashboard
        ↓
Can access:
  - Church Settings (branding, colors, content)
  - Manage Resources
  - View Analytics
  - Church Information
```

```
"Start for your church" clicked
        ↓
Step 1: Basic Details
  - Church name
  - Admin name

        ↓
Step 2: Branding

  - Preview
        ↓

Admin Dashboard

## Security & Privacy

### Privacy Principles

1. **No Public Church Discovery**: Churches are invitation-only; no searchable directory
2. **Pre-Login Church Selection**: Users must know their church to access the system
3. **Tenant Data Isolation**: Complete separation between church data
4. **Member-Only Content**: Resources and information only visible to authenticated members

### Authentication Flow

```
1. User selects church from list (requires prior knowledge)
2. Church selection sets theme context
3. Login screen styled to church brand
4. Authentication validates against church tenant
5. Access granted to church-specific content only
```

### Data Privacy

- Members can only see their own church's data
- Church admins cannot access other churches' information
- Platform admins have elevated access for support
- Personal information is church-specific

### Future Security Enhancements

- OAuth integration
- Two-factor authentication
- Role-based access control (RBAC)
- Audit logging
- Data encryption at rest

### Theme Application Pattern

All tenant-level components follow this pattern:

```typescript
export function ScreenName({ church, ...props }) {
  const theme = generateChurchTheme(church);
  
  return (
    <div style={theme.backgroundStyle}>
      <header style={{
        background: withOpacity(church.color, 0.95),
        borderColor: theme.cardBorder
      }}>
        {/* Church branding */}
      </header>
      
      <main>
        <Card style={{
          background: theme.cardBg,
          borderColor: theme.cardBorder
        }}>
          {/* Content */}
        </Card>
      </main>
    </div>
  );
}
```
